Phase 1 — Why Now

Why MCP? What Copilot Can't Do Alone

Plain Copilot — working blind

  • Guesses design tokens from training data — often wrong or stale
  • Cannot read your actual Jira tickets or acceptance criteria
  • Generates locators from static code — breaks when UI changes
  • Pastes entire files into context — window fills up fast
  • No access to live systems: DOM, design files, repos

Copilot + MCP — working with real data

  • Figma MCP → reads your actual design frame on demand
  • Atlassian MCP → queries live Jira ACs and Confluence pages
  • Playwright MCP → inspects the live DOM by semantic label
  • Tools return only the slice the model needs — no context bloat
  • One prompt spans design → code → test → repo

Phase 2 — Concepts

What Is MCP?

A standard protocol that gives AI assistants callable tools, readable data, and pre-baked instructions — across any language model, any IDE, any server.

🔧 Tools

Functions Copilot can invoke. Execute code, make API calls, return results. This is what we use 90% of the time.

get_code · get_variable_defs · run_test

📄 Resources

URIs Copilot can read. Files, database views, API snapshots — passive data attached to the context.

design-tokens:// · jira://sprint/current

💬 Prompts

Pre-baked instruction templates with parameters. Appear in the IDE slash-command menu.

/summarise-sprint · /review-pr
Transport layer — how VS Code connects to MCP servers
⚡

stdio — Local Process

Playwright MCP

Server runs on the same machine as VS Code. Talks over stdin/stdout — no open port, no TLS overhead.

  • Auth via process environment variables — no OAuth needed
  • VS Code spawns the process via npx / uvx command
  • Isolated per session — terminates when chat ends
  • Lowest latency — in-process pipe
🌐

Streamable HTTP — Remote

Figma MCP

Server is a remote HTTPS endpoint. GA since 2025-03-26, replaces the legacy SSE transport.

  • Auth: OAuth 2.1 + PKCE — VS Code handles the browser flow
  • Single endpoint: POST /mcp with chunked streaming response
  • PAT fallback: store token via ${input:token-name} in mcp.json
  • Vendor-hosted — e.g. https://mcp.figma.com/mcp

Phase 2 — VS Code

Connecting MCPs in VS Code

How it works

  1. Add .vscode/mcp.json to your repo
  2. Reload VS Code: Ctrl+Shift+P → "Reload Window"
  3. Open Copilot Chat → switch to Agent mode
  4. Copilot auto-discovers available tools via tools/list
  5. Type a natural language prompt — Copilot picks the right tool

✅ Commit .vscode/mcp.json to Bitbucket — your whole team inherits the same MCP configuration automatically. No per-developer setup.

🔑 Use "${input:jira-token}" for secrets — VS Code prompts on first call and stores securely. Never hard-code credentials.

// .vscode/mcp.json — commit this to your repo
{
  "servers": {
    // Figma MCP (remote)
    "figma": {
      "type": "http",
      "url": "https://mcp.figma.com/mcp"
      // or desktop: "http://127.0.0.1:3845/mcp"
    },

    // Playwright MCP (local)
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["@playwright/mcp@latest",
               "--allowed-origins=https://*.your-domain.com"]
    },

    // Atlassian MCP
    "atlassian": {
      "type": "http",
      "url": "https://mcp.atlassian.com/v1/mcp",
      "headers": {
        "Authorization": "Bearer ${input:atlassian-token}"
      }
    }
  }
}
Phase 2 — Configuration

Generating Tokens for MCP Authentication

🎨 Figma PAT

  1. Go to figma.com → Profile icon → Settings
  2. Scroll to Personal access tokens
  3. Click Generate new token
  4. Set scopes: File content: Read, Dev resources: Read
  5. Copy token — shown once only
  6. VS Code prompts on first MCP call → stored in OS keychain

🔗 Atlassian API Token

  1. Go to id.atlassian.com → Security → API tokens
  2. Click Create API token
  3. Label: mcp-atlassian
  4. Copy token immediately — shown once
  5. Reference in mcp.json as ${input:atlassian-token}

One token covers Jira + Confluence + Bitbucket.

🎭 Playwright MCP No token — local process

Playwright MCP runs as a local stdio process — no API key needed. Just verify Node 18+ is installed:

npx @playwright/mcp@latest --version

If this prints a version number, you're ready — no auth steps required.

🔑 Never paste tokens directly into mcp.json. Use "${input:token-name}" — VS Code prompts on first call and stores the value in the OS credential store. The committed file contains no secrets.

Phase 3 — Techniques

Prompt Craft & Context Management

🎨 Figma MCP

  • "Get colour tokens from the design system in Figma"
  • "Generate a React Native button from this Figma frame: [URL]"
  • "Export only colour tokens — not all variables"

Key: supply a frame URL or say "from Figma" to invoke.

📋 Atlassian MCP — Jira

  • "Get the ACs from Jira story PROJ-1234"
  • "List all open stories in the current sprint"
  • "Find the Figma link attached to this Jira ticket"

Key: name the story ID or sprint — Copilot won't guess it.

🎭 Playwright MCP

  • "Navigate to the app login page and find the submit button selector"
  • "Open a browser and generate a Playwright test for the signup flow"
  • "Update broken locators by opening the live page"

Key: "navigate to" or "open a browser" triggers the tool call.

🔀 Atlassian MCP — Bitbucket

  • "Push this code to a new branch named feat/PROJ-1234"
  • "Create a PR from feat/PROJ-1234 to main with this description"
  • "Get the diff for PR #42 in the app repo"

Key: name the repo, branch, and PR number explicitly.

Build Your Own

Building Your Own MCP Server

An MCP server exposes tools, resources, and prompts to AI agents via a standard JSON-RPC 2.0 protocol — making any internal API or private service directly accessible to Copilot.

🔨 When to build custom

  • No vendor server covers your internal tool or private API
  • Self-hosted or on-premise tools not accessible publicly
  • Custom business logic or scoping before returning context
  • Team needs a purpose-built integration with fine-grained control

✅ When to use existing servers

  • Figma MCP — official first-party server, prefer it
  • Playwright MCP — first-party, use for browser automation
  • Atlassian MCP — official vendor server for Jira & Confluence
  • Always prefer a well-maintained first-party server for public SaaS tools
Three server primitives
⚡ Tools Callable functions — model-controlled
📂 Resources Read-only context — app-controlled
💬 Prompts Reusable templates — user-controlled
🖥
stdio — local subprocess, no network overhead, single client
🌐
Streamable HTTP — remote HTTPS, multiple clients, OAuth 2.1
Build Your Own

Use Case A: Custom Jira MCP Server

Why build custom vs Atlassian official?

  • Works on self-hosted or on-premise Jira — not only Jira Cloud
  • No dependency on third-party approval — deploy and run immediately
  • Apply custom logic: field filtering, read-only mode, custom scopes
  • Teams build deeper MCP understanding by creating, not just consuming

4 tools to implement

jira_get_issue(issueKey)
jira_search_issues(jql, maxResults?)
jira_create_issue(project, summary, type)
jira_add_comment(issueKey, body) 
// jira_get_issue — handler excerpt
server.tool(
  "jira_get_issue",
  "Fetch a Jira issue: summary, ACs, status",
  { issueKey: z.string().describe("e.g. PROJ-1234") },
  async ({ issueKey }) => {
    const res = await fetch(
      `${process.env.JIRA_BASE_URL}`
      + `/rest/api/3/issue/${issueKey}`,
      { headers: {
        "Authorization": `Bearer ${process.env.JIRA_API_TOKEN}`,
        "Accept": "application/json",
      }}
    );
    if (!res.ok) return {
      isError: true,
      content: [{ type: "text",
        text: `Jira error ${res.status}` }],
    };
    const { fields } = await res.json();
    return { content: [
      { type: "text", text: JSON.stringify(fields) }
    ]};
  }
);

Wire in mcp.json — secrets via VS Code input variables

"jira-custom": { "type": "stdio", "command": "npx", "args": ["tsx", "src/server.ts"],
  "env": { "JIRA_API_TOKEN": "${input:jira-api-token}", "JIRA_BASE_URL": "https://your-jira.example.com" } }

When MCP Isn't Available: Context Fallbacks

Not every server may be available when your team needs it. These fallbacks deliver most of the value without a live MCP connection — useful when a server isn't yet wired up.

🎨 No Figma MCP?

Export screens as a zip:

  • In Figma: select frames → Export as PNG + JSON spec → zip
  • Attach the zip to your Copilot agent chat
  • Prompt: "These are our design specs. Generate a React Native button matching screen-2.png"

⚠️ Best for small, scoped screens. Export one frame at a time — large files get noisy.

📋 No Atlassian MCP?

Export Jira story as HTML:

  • In Jira: open story → Print / Export as HTML
  • Save to specs/PROJ-1234.html in your repo
  • Prompt: "Read specs/PROJ-1234.html and generate test cases for each AC"

✓ Works today — open the file in VS Code or attach it to your Copilot agent chat.

🎭 No Playwright MCP?

Record tests offline with Playwright CLI:

  • Run npx playwright codegen [url] locally to record clicks into a test file — no MCP connection needed
  • Open browser DevTools → Elements → right-click element → Copy selector for manual locator hunting
  • Paste the generated test into Copilot chat: "Clean up these selectors to use getByRole instead of XPath"

✓ Works today — Playwright CLI is already available if Node.js is installed.

Phase 7 — Security

OWASP MCP Top 10: What Matters as a User

RiskWhat it means for youHow to protect yourself
Tool Poisoning A malicious tool description secretly instructs the LLM to exfiltrate data or take harmful actions — without you seeing it. 84.2% success rate with auto-approve. Vendor-official only Review tool descriptions before approving. Enable tool-call confirmation in VS Code settings.
Rug Pull A server's description changes after you approved it (npm update, remote server update). New behaviour, original approval no longer applies. Pin versions Use @1.29.0 not @latest. Review changelogs before upgrading MCP server versions.
Tool Shadowing Two servers register the same tool name. The malicious one is called instead of the trusted one. Namespace awareness Check for duplicate tool names when adding a new MCP. Prefer servers with namespaced tool names (figma_get_code not just get_code).
Excessive Agency Auto-approve mode lets Copilot call any tool without confirmation. A chained prompt injection can trigger destructive calls. Never auto-approve destructive tools Require confirmation for any tool that writes, creates, deletes, or triggers a build.
Credential Exposure API tokens hard-coded in mcp.json or leaked via error logs. Committed to Bitbucket = visible to all repo members. VS Code input vars Use "${input:token-name}". Never hard-code. Rotate tokens after any accidental commit.
Prompt Injection via Resources A file or URL fetched by an MCP resource contains text that hijacks the model's instructions. Treat resource content as untrusted Don't give resources from external URLs the same trust as tool outputs from approved servers.
Phase 8 — Best Practices

7 Best Practices for Using MCP Servers

1. Vendor-official servers only

Only use vendor-official servers or internally reviewed servers. Avoid unreviewed community servers without a security assessment.

2. Pin server versions

Use explicit versions in mcp.json (e.g. @playwright/mcp@1.50.0 not @latest). Review changelogs before upgrading.

3. Secrets via VS Code input vars

Use "${input:token-name}" for all API tokens. VS Code prompts once and stores in the OS keychain. Never commit credentials to Bitbucket.

4. Confirm before destructive actions

Enable tool-call confirmation in VS Code for any tool that writes, triggers builds, creates issues, or modifies files. Auto-approve only for read-only tools.

5. Scope your prompts

Ask for specific slices, not entire datasets. "Export only colour tokens" not "export all tokens". This prevents context bloat and faster responses.

6. Commit .vscode/mcp.json to Bitbucket

Share your MCP configuration with the team. Everyone gets the same setup. Include a comment in the file explaining each server and its status.

7. Task framing, not question framing

Prompts that describe a task invoke MCP tools. Prompts that ask a question get answered from training data. Use "get from Figma" not "what are the brand colours".
